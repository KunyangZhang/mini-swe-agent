## 1. 成功批次之后仍保留旧格式错误计数

时序：一次 FormatError → 一次正常 shell 动作 → ready 检查点刚落盘即 `os._exit(77)` → 恢复后又一次 FormatError。

原实现的 `execute_actions()` 先保存 ready 检查点，`DefaultAgent._run_loop()` 随后才清零连续格式错误计数。中断后恢复到旧计数，把不连续的两次错误误判为连续，提前返回 `RepeatedFormatError`。正常未中断运行不应因此终止。

修复：在成功生成观察、切换 ready 时清零计数，再落盘。恢复后第二次错误仍可恢复，第四次模型调用正常提交；真实 shell 的 `clean` 文件只有一行，已完成动作没有重跑。

## 2. 恢复或继续批次绕过总时间预算

原实现仅在下一次模型 query 前检查总时间。两条失败复现分别是：

1. 保存模型回复后退出，等待预算到期再恢复，仍启动写文件和提交命令，错误地返回 Submitted。
2. 同批次第一条 shell 执行跨过期限，第二条仍继续产生副作用。

这对应原 FORK_README 已承认的预算限制；本次将它实做补强，不声称发现了从未被披露的问题。

修复：将 RunStore 的只读结果查询提取为 `result()`；先检查动作历史。未知结果仍优先报 `AmbiguousActionError`；已落盘/经核验的结果仍可读取。只有真正未开始的动作才检查总时间，并且在检查通过后才写 intent、启动 shell。超时拒绝不会制造“明知没执行但被标成未知”的假 intent。

修复后：恢复场景无新增 action 行、无文件副作用；批次场景只保留第一条动作及结果，第二条未开始，返回 TimeExceeded。**TimeExceeded 是预算终止，不算任务成功。** 仍未实现对已运行命令的全局硬截止、对模型请求的硬截止或分布式时钟保证；单条工具超时继续使用上游环境逻辑。

## 5. 真实模型验证

使用 AutoDL RTX 4090 D，Qwen/Qwen2.5-Coder-3B-Instruct，本地 BF16、greedy、每次最多 768 输出 token、最多 12 轮、总时间预算 600 秒、单工具 30 秒。没有付费 API 调用；GPU 租赁费用未取得账单，不填 0。

这是一个人工构造的小任务的集成验证，不是 SWE-bench，不是统计意义的模型成功率对照。脚本回放和真实生成分别保存；真实模型的提示、响应、token 数和计时来自实际推理。模型权重版本、依赖、哈希与各次运行条件另存证据。

两组条件各有三种运行策略：DefaultAgent 不中断、DurableAgent 不中断、DurableAgent 在首个真实回复落盘后退出 77 再恢复。第一组仅给任务描述与文件名；第二组额外给初始源码和完整测试。固定相同模型、greedy、768 输出 token/轮、12 轮上限；第二组是显式改变输入条件的诊断对照，不能混为同条件重复或选择性只报最好结果。

**实际结果：六次运行全部达到 LimitsExceeded，最终独立测试均未通过，源文件均未修改成功。** 两组均观察到模型反复对不匹配的函数/代码执行 sed，且把 pytest 与提交标记合并在同一命令中；由于提交标记不是输出第一行，不满足上游提交协议。提供源码上下文未能纠正此行为。没有继续加轮数或挑选成功样本。

据此只能确认本地生成—shell—观察—恢复链路实际运行，以及该小模型/提示组合在此任务上失败。不能推导普遍模型失败率、Harness 提高模型能力或任意真实模型都能完成编码任务。
